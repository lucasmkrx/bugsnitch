# Architecture

The Rust HTTP service exposes workspace-scoped desired state in PostgreSQL. The public homepage is served at `/`. The React workspace at `/app/` reads snapshots scoped to the signed-in owner or named member. The runner connects outbound. It owns its SQLite execution journal, Git worktrees and local model subprocess. GitHub owns ticket content, open state, PRs and required checks. Sentry supplies evidence about connected applications.

Workspace sessions, pairing grants, device credentials, GitHub App installation tokens, plugin credentials and Codex sign-in have different authorities. The owner issues operator or approver credentials for a workspace or one project. The Rust service resolves the session and its scope, and the domain worker checks each requested operation against the authenticated role. Pairing grants expire and can be redeemed once. Device assignments limit which project metadata a machine can publish. The local runtime owns model authorization. Hosted inference remains unavailable pending a documented applicable route.

A disconnected machine retains ownership of work. Last contact describes connectivity. Completion requires durable evidence from the owning runner. Raw logs, issue text, repository content and webhook payloads are untrusted inputs. Local execution assumes an owner-reviewed repository and validation configuration. A worktree shares Git metadata and the OS user.

## Native runner and storage components

The runner calls a sibling Rust process over private STDIO for both SQLite files. Typed attempt checkpoints, summaries and controls reuse a verified connection to the runner journal. The helper checks that the database file still matches the open handle on each use. Device synchronization reads mappings and acknowledged ownership together from the device journal. Compatibility SQL uses an isolated connection for each batch. An interrupted transaction rolls back when its connection closes. If the reply is lost after a commit, the caller reconciles against durable attempt or receipt records. Only trusted local code constructs requests. The device protocol exposes typed commands.

The same packaged Rust binary has separate private entry points for Git worktree operations and validation. The Go CLI supplies the recorded local subject, checks hosted authority and owns the stage sequence. Rust checks the checkout against Git's registration and the expected revision, then runs the approved validator in its own process group. A private pipe ties its lifetime to the foreground runner. Closing the pipe requests termination. A terminal receipt identifies the observed outcome. Rust commits the final attempt version and completes pending local controls in a single SQLite transaction. [Execution decision](decisions/0005-native-runner-execution.md)

The Rust `bugsnitch-server` executable owns the public listener, session cookies, origin checks, the dashboard, REST routing, webhook verification, OAuth introspection and MCP. Its authenticated device operations use a bounded pool of Rust coordinators. Each PostgreSQL operation owns its transaction. The hosted server checks its native path and private application worker on readiness. [Hosted coordination decision](decisions/0006-hosted-coordination.md)

Rust reads dashboard state, diagnostics and the three MCP lists from PostgreSQL. Dashboard queries resolve the unexpired session, member revocation and project restriction in the same database snapshot as the returned records. Diagnostics require the owner. MCP lists use the authenticated owner grant. The listener forwards bounded JSON without rebuilding every object. The private Go application worker applies plan and policy changes, runs retention and consumes provider work reserved by the native scheduler. Rust sends named operations with an authenticated actor across an owner-only Unix socket. The worker rechecks the actor’s workspace, permitted operation, project scope and applicable subject versions. It sends GitHub operations to a private Rust executable that signs App JWTs, requests installation tokens and performs the scoped HTTPS requests. REST, MCP and GitHub changes all reach the same durable state. [HTTP migration decision](decisions/0007-rust-http-and-providers.md)

## Local admission

The person starts a local run. On enrolled computers, each admission checks credential revocation, workspace, repository mapping, project pause and the approved criteria hash when a plan exists. A PostgreSQL transaction locks the workspace before reserving ticket capacity or a model permit. Waiting releases active execution capacity and retains the issue and shared locks. The runner journals pending requests and sequence numbers to reconcile a lost acknowledgment. A missed heartbeat never releases a reservation. Global limits apply only to enrolled processes participating in the protocol.

The dashboard reads persisted, bounded reports. An attempt version advances on the owning device and cannot change device, issue or base. Requests to control an attempt carry the reviewed version. A machine receives only typed operations bound to its current credential and assignments. Stop and pause remain requests until the runner acknowledges their disposition. Full worktree evidence stays local unless a specific field is included in the device protocol.

Owner proposals are immutable versions. Approval checks the current project version. A new plan cannot replace another plan while work remains owned. Among eligible tickets, selection orders by priority, active Linear delegation and canonical issue number. Owner-attested integration evidence unlocks prerequisites and reservations serialize declared workspace resources. Configured dates distinguish a target and an estimate. GitHub issue checks remain necessary at execution.

## One issue through review

1. A plan can bind existing issues or propose new ones. Publishing a proposal creates PostgreSQL write intents. Only confirmed GitHub issue numbers enter an execution plan. Material issue changes advance a generation and invalidate the prior binding.
2. A paired runner requests eligibility and independently rereads the selected GitHub issue. The local owner supplies a trusted checkout, allowed files and validation argv. PostgreSQL grants attempt ownership and serializes access to limited resources. SQLite records the base, branch, worktree and current stage.
3. Each local model turn requires its own permit. The implementer receives only the selected context. A trusted local component applies edits to approved files and runs the configured validator. A separate read-only review session receives the candidate diff, criteria and validation evidence.
4. The runner synchronizes stage metadata. Sharing a diff requires the owner to preview and approve its digest. After the dedicated branch is published, the service can open a draft PR through its App. A PR inspection binds observations to the head, target, scope and policy at inspection time. The retained local candidate and review artifacts identify the work independently of the PR.

A runner uses the signed-in local Codex runtime by default. A registered worker stage can instead call the Claude Messages API directly with a runner-side key. Dashboard messages retain their hosted-inference status. Paired runners can sync model IDs and provider-reported token counts for workspace metering. The local project-manager command keeps a bounded context in the runner's journal. The scope of an MCP grant limits which of the same hosted operations a compatible client can call. ## Reconciliation and evidence

GitHub and Sentry handlers validate the signature against the original request bytes, resolve an authorized installation and project, and persist the permitted event fields. Workers process accepted data and write intents under database coordination. A lost provider response leaves an uncertain intent. The integration checks the provider for its recorded marker before another write. Changes observed from GitHub can invalidate ticket eligibility and PR evidence.

An owner can authorize protected delivery of a signed-off revision on an enrolled repository. The service verifies the GitHub merge group before publishing its check. GitHub enforces the repository rules and performs the merge. Ordered releases also check the recorded status of earlier stages in the specified environment.

Incident grouping preserves release and environment observations within one incident. A validated candidate, a deployment receipt and positive environment validation are distinct facts. Re-evaluation after a rollback or contradictory fixed-build occurrence preserves the earlier evidence. [Provider contracts](PROVIDERS.md) · [Pull-request and merge gates](INTEGRATION_QUEUE.md)

The hosted HTTP service owns provider integration credentials. Its startup migrator receives PostgreSQL connection settings. macOS devices hold their own scoped service credentials, project mappings and runtime association. The independent dashboard and ChatGPT bridge see only data allowed by their respective grants. Worktree isolation and credential limits are described in the [runner guide](RUNNER.md).
