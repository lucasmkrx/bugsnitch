# Local model authorization

Bugsnitch uses the installed Codex app-server over private, newline-delimited JSON on stdin/stdout. The local owner initiates all inference in this slice. Start with `codex login` using the supported ChatGPT sign-in flow, then `bugsnitch models` for model discovery and `bugsnitch proof` for a one-turn execution check. Put the checked Codex binary on PATH for both the terminal and any user service. No ChatGPT window needs to stay open. If the runtime loses its session, use the supported local sign-in flow again. The runner does not read Codex credential files.

## Integration envelope checked November 21, 2026

The official app-server documentation describes the Codex-managed ChatGPT account route for local or open-source integrations. Codex owns authentication, storage, renewal and revocation. The local CLI explicitly selects the OpenAI provider and ChatGPT login mode. It checks the account type before inference. Its child environment includes only local runtime settings. [App-server authentication](https://developers.openai.com/codex/app-server) · [Codex sign-in](https://developers.openai.com/codex/auth)

The vendor directs commercial or hosted services to Sign in with ChatGPT. The plan-usage preview documentation directs paid and remotely hosted apps to request access. Operating a hosted dashboard that triggers execution on a personal computer needs an applicability determination for that deployment. The next external step is to submit the deployment and data-flow description through the official interest route and obtain an applicable answer. A technical request or a locally working turn does not settle that question. Dashboard and MCP actions cannot start inference in this build. [Availability and access request](https://developers.openai.com/siwc/token-sharing-open-source) · [App-server integration for separately authorized plan usage](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) · [Preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

The adapter is pinned to `codex-cli 0.171.0-alpha.13`, the version supplied on the development machine. Its protocol is experimental. Before changing the pin, generate the version's schemas with `codex app-server generate-json-schema --out DIRECTORY` and repeat the live check. The adapter calls `initialize`, `initialized`, `account/read`, checks available tools, discovers models with `model/list`, and invokes `thread/start` and `turn/start`. It binds events to both thread and turn identities, extracts the final agent message and waits for a completed terminal status. The runner retains concise observable artifacts instead of reasoning streams. A successful RPC handshake confirms protocol access only.

The local worker, planner and reviewer run in fresh ephemeral read-only sessions with a temporary working directory. The trusted runner supplies selected text, applies authorized edits and invokes the separate validator. Transcripts, attempted commands and account objects are never synchronized to the hosted API. The authenticated model provider receives the deliberately shared task context. Supported reasoning settings come from the model catalog. Use `model` and `reasoning` in a local project configuration to override the runtime default. Model discovery does not establish entitlement. Credential errors, usage exhaustion, rate limits, absent models and transport failures produce distinct failure messages where Codex supplies those codes. Run `bugsnitch usage` to read measured primary and secondary windows and, where supplied, the ordinary-usage permission. The CLI preserves unknown fields as null and emits no account ID or dollar estimate. Plan usage may be shared across the user's work. [Accounts, credentials and shared usage](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)
