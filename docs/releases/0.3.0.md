# Bugsnitch 0.3.0 preview

Investigate a saved line, compare historical files and record evidence without changing your checkout.

- Preview per-file patches, compare merge parents, open read-only native diffs, and follow rename history.
- Mark known-good and known-bad commits, validate their ancestry, freeze candidates and record your own assessment.
- Explicitly export notes and commit metadata to JSON. Closing the panel discards its in-memory session.
- Restore investigation context after webview recreation; cancel stale editor requests.
- Validate production webview accessibility and install the exact checked VSIX in an isolated VS Code profile.

## Install

Download `bugsnitch-0.3.0.vsix`, check `SHA256SUMS`, and run **Extensions: Install from VSIX…**. Requires VS Code 1.105.0+, Git 2.39+, Node 24 only for contributors, and a trusted local workspace. See the [guided demo](https://github.com/lucasmkrx/bugsnitch/blob/main/docs/demo.md).

This is a GitHub preview under `bugsnitch-dev-placeholder`. A permanent publisher is still required for Marketplace distribution. Changing publisher changes the extension identity. Assessments are manual; blame and candidate ranges do not establish causation. No automatic classifier or bisect is provided.

Inspection is local, with no telemetry or runtime network access. Source is MPL-2.0; branding has separate terms. Package inventory and SHA-256 are validated before the installed-artifact smoke. See the source validation guide for tested scope and limitations.
