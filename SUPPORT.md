# Support

For help getting started, use the guide for the part of Bugsnitch you are running.

- To try the bundled checkout or sign in to a local workspace, follow the [quickstart](README.md#try-it-locally) and [dashboard guide](docs/DASHBOARD.md).
- For pairing, worker configuration, waiting attempts or local recovery, start with the [runner guide](docs/RUNNER.md).
- For a blocked PR or an inconclusive deployment verdict, see [PR inspection and queue delivery](docs/INTEGRATION_QUEUE.md) and [deployment verification](docs/PROVIDERS.md#github-deployment-monitor).
- For self-hosting, migrations, backup or restore, use the [operations guide](docs/OPERATIONS.md).

Report reproducible bugs or propose features through [GitHub Issues](https://github.com/lucasmkrx/bugsnitch/issues/new/choose). Include the Bugsnitch commit or version, affected component, operating system and steps to reproduce. For delivery problems, include the stage and the status you observed. Redact credentials and private repository content. Support is best-effort during the developer preview.

Report suspected vulnerabilities through [private security reporting](SECURITY.md).
