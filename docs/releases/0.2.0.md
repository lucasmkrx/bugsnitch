# Bugsnitch 0.2.0 preview

Trace a saved line, inspect its associated commit, and follow real ancestry without changing your checkout.

- Stable graph lanes represent branches, merges, and parents beyond the loaded page.
- **Show in graph** and parent inspection connect line evidence to surrounding history.
- Browse local branches, remote-tracking refs, and commit tags without checkout or fetch.
- Investigation context survives refresh, pagination, and entry-point changes.

## Install

Download `bugsnitch-0.2.0.vsix` from this release. In VS Code, run **Extensions: Install from VSIX…** and select the file. Requires VS Code 1.105.0+, system Git on PATH, and a trusted local Git workspace.

Open a Git repository and run **Bugsnitch: Open**. To trace code, select a saved line and run **Bugsnitch: Snitch on Current Line**. Follow the [guided demo](https://github.com/lucasmkrx/bugsnitch/blob/v0.2.0/docs/demo.md) for a reproducible investigation.

This is an early development preview distributed through GitHub. Its temporary publisher is `bugsnitch-dev-placeholder`; it is not a Marketplace release. Changing publisher later will change the extension identity. Line attribution is an investigation lead, not proof of a regression. Regression ranges, bisect, and automatic regression identification are not implemented.

Inspection runs locally with no account, telemetry, or network requests. Source is MPL-2.0; Bugsnitch branding has separate terms. See the bundled license and trademark documents.

`SHA256SUMS` records the VSIX checksum. Release automation validates the source and VS Code host checks before packaging this artifact.
